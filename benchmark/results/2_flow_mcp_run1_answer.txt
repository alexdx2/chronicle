## Request Chain (ordered)

**1. `POST /arena/attack` → `arena-api` · `ArenaController`**
- Body: `{ weaponType: string }`
- `@UseGuards(BattleGuard)` runs first — checks `new Date().getHours()` is between 6–22. Returns `403` outside that window.

**2. `ArenaController.attack()` → `ArenaService.tomAttacksJerry(weaponType)`**

**3. `ArenaService` → `TomClient.getStatus()`**
- HTTP GET `http://tom-api:3001/tom/status`
- Hits `tom-api` · `TomController.getStatus()` → `TomService.getStatus()`
- Queries `tom-api` DB: `prisma.cat.findFirst({ where: { name: 'Tom' }, include: { weapons: true } })`
- Returns `{ id, name, health, speed, mood, weapons[] }`

**4. `ArenaService` → `JerryClient.getStatus()`**
- HTTP GET `http://jerry-api:3002/jerry/status`
- Hits `jerry-api` · `JerryController.getStatus()` (with `TrapInterceptor` applied to controller — logs "Checking for active traps…" before/after)
- → `JerryService.getStatus()` → `prisma.mouse.findFirst({ where: { name: 'Jerry' }, include: { traps: true } })`
- Returns `{ id, name, health, speed, clever, traps[] }`

**5. `ArenaService` → `JerryClient.getTraps()`**
- HTTP GET `http://jerry-api:3002/jerry/traps`
- Hits `jerry-api` · `JerryController.getTraps()` (again through `TrapInterceptor`)
- → `JerryService.getTraps()` → `prisma.trap.findMany({ where: { isSet: true } })`
- Returns active traps `[]`

**6. `ArenaService` — battle resolution logic**
- If `activeTrap` exists → `result = 'TRAP_TRIGGERED'`, `damage = 0`
- Else if `jerry.speed > tom.speed + 20` → `result = 'JERRY_DODGES'`, `damage = 0`
- Else → `result = 'TOM_HITS'`, `damage = 25`

**7. `ArenaService` → `arena-api` DB write**
- `prisma.battleEvent.create({ data: { tomId, jerryId, weapon, trap, result, damage } })`
- Writes to `arena-api`'s own PostgreSQL DB

**8. `ArenaService` → `BattleResultProducer.publish(event)`**
- Publishes to Kafka topic `battle-results`
- (Implementation stub: logs to console; production would call `kafka.producer.send(...)`)

**9. Response returned** — `{ ...battleEvent, tom: tom.name, jerry: jerry.name }`

## Cross-Service Calls

| From | To | Transport | Endpoint |
|------|----|-----------|----------|
| `arena-api` | `tom-api` | HTTP GET | `GET /tom/status` |
| `arena-api` | `jerry-api` | HTTP GET | `GET /jerry/status` |
| `arena-api` | `jerry-api` | HTTP GET | `GET /jerry/traps` |

Both `TomClient` and `JerryClient` use native `fetch`. Errors from Tom throw a 4xx/5xx upstream; errors from Jerry's traps endpoint silently return `[]`.

## Async Side Effects

**Kafka → `spectators-api`**
- `BattleResultProducer` publishes the `BattleEvent` to the `battle-results` Kafka topic
- `spectators-api` · `BattleResultConsumer` is subscribed via `@EventPattern('battle-results')`
- On receive: calls `SpectatorService.recordBattle(event)` — appends to an in-memory `battles[]` array

**Note:** `NotificationService` exists in `spectators-api` (with methods `notifySpectators()` → `POST http://notifications:3005/push` and `sendDailyDigest()` → `POST http://notifications:3005/email/digest`) but it is **not wired** into `SpectatorsModule` and is **not called** from `BattleResultConsumer`. It is dead code in the current flow.

**`BattleGateway` (WebSocket)** exists in `arena-api` with a `broadcastBattleResult()` method that would emit `battle-result` to all connected Socket.io clients, but `ArenaService.tomAttacksJerry()` does **not call it** — so no WebSocket broadcast is triggered by `POST /arena/attack` directly.

Each service owns its own PostgreSQL database (separate Prisma schemas). No shared DB.
