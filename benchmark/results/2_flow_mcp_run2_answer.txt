## Request Chain (ordered)

1. **`BattleGuard`** — `arena-api/src/arena/battle.guard.ts`
   - Validates current hour is between 6–21 (6am–9:59pm); returns HTTP 403 outside that window

2. **`ArenaController.attack(body: { weaponType: string })`** — `arena-api/src/arena/arena.controller.ts`
   - Route: `@Post('attack')`, body is inline-typed (no DTO class)

3. **`ArenaService.tomAttacksJerry(weaponType)`** — `arena-api/src/arena/arena.service.ts`
   - Step 1: calls `TomClient.getStatus()` → `GET tom-api:3001/tom/status` → `TomService.getStatus()` → reads `Cat` + `CatWeapon` tables
   - Step 2: calls `JerryClient.getStatus()` → `GET jerry-api:3002/jerry/status` → `JerryService.getStatus()` (with `TrapInterceptor`) → reads `Mouse` table
   - Step 3: calls `JerryClient.getTraps()` → `GET jerry-api:3002/jerry/traps` → `JerryService.getTraps()` (with `TrapInterceptor`) → reads `Trap` table where `isSet = true`
   - Step 4: evaluates outcome:
     - Active trap found → `TRAP_TRIGGERED`, damage = 0
     - `jerry.speed > tom.speed + 20` → `JERRY_DODGES`, damage = 0
     - Otherwise → `TOM_HITS`, damage = 25
   - Step 5: `PrismaService.battleEvent.create(...)` — INSERT into `BattleEvent` table
   - Step 6: `BattleResultProducer.publish(event)` — publish to Kafka topic `battle-results`

4. **Response returned** to HTTP caller: full `BattleEvent` record + `tom.name` + `jerry.name`

---

## Cross-Service Calls

| From | To | Method | Endpoint | Purpose |
|---|---|---|---|---|
| arena-api | tom-api | GET | `http://tom-api:3001/tom/status` | Fetch Tom's speed, health, weapons |
| arena-api | jerry-api | GET | `http://jerry-api:3002/jerry/status` | Fetch Jerry's speed, health |
| arena-api | jerry-api | GET | `http://jerry-api:3002/jerry/traps` | Fetch active traps (where `isSet=true`) |

**Error handling:** `TomClient.getStatus()` and `JerryClient.getStatus()` throw `HttpException` on non-OK responses; `JerryClient.getTraps()` returns `[]` on failure (silent fallback).

Both Jerry endpoints pass through **`TrapInterceptor`** on the jerry-api side (logs trap activation).

## Async Side Effects

**Kafka topic: `battle-results`**

- **Producer:** `BattleResultProducer.publish(event)` — `arena-api/src/arena/battle-result.producer.ts`
  - Message payload: full `BattleEvent` record (id, tomId, jerryId, weapon, trap, result, damage, round, createdAt)
  - ⚠️ Current implementation only `console.log`s — production Kafka send is stubbed out

- **Consumer:** `BattleResultConsumer.handleBattleResult(event)` — `spectators-api/src/spectators/battle-result.consumer.ts`
  - Decorated with `@EventPattern('battle-results')`
  - Calls `SpectatorService.recordBattle(event)` which **appends to an in-memory array** (`this.battles.push(event)`) — no database write in spectators-api

**WebSocket gateway (`BattleGateway`):** Initialized in `ArenaModule` but `broadcastBattleResult()` is **not called** during the attack flow — it exists but is dead code in this path.

**Bull queue (`BattleQueueProducer/Consumer`):** Defined in `arena-api/src/arena/battle.queue.ts` but **not invoked** by the attack endpoint — the service is called directly, not via the queue.

## Data Models Touched

| Service | Model | Table / Prisma Model | Operation | Fields Read/Written |
|---|---|---|---|---|
| tom-api | `Cat` | `Cat` | READ | `id`, `name`, `health`, `speed`, `mood` |
| tom-api | `CatWeapon` | `CatWeapon` | READ (via relation include) | `id`, `name`, `damage`, `type`, `ownerId` |
| jerry-api | `Mouse` | `Mouse` | READ | `id`, `name`, `health`, `speed`, `clever` |
| jerry-api | `Trap` | `Trap` | READ | `id`, `name`, `effect`, `ownerId`, `isSet` |
| arena-api | `BattleEvent` | `BattleEvent` | INSERT | `tomId`, `jerryId`, `weapon`, `trap?`, `result` (enum), `damage`, `round` (default 1), `createdAt` |

**`BattleResult` enum values** (arena-api): `TOM_HITS`, `JERRY_DODGES`, `TRAP_TRIGGERED`, `MUTUAL_DESTRUCTION`  
— `MUTUAL_DESTRUCTION` is defined in the schema but unreachable through current attack logic.

**spectators-api** has no database — battle events are stored purely in-memory in `SpectatorService.battles[]`.
